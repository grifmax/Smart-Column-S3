## Стратегические фичи / изюминка проекта

Цель этого блока - вывести Smart-Column S3 из уровня "еще одна автоматика для колонны" в уровень ассистента повторяемого процесса: система не только управляет режимами, но и объясняет оператору состояние колонны, адаптирует рецепт под реальные условия, сравнивает прогоны и предлагает улучшения.

### Digital Master Distiller / Smart Run Advisor

- [x] **Run Advisor v1: послепроцессный отчет** - после завершения режима формировать понятный отчет: длительность фаз, расход энергии, объемы фракций, стабильность колонны, срабатывания safety, отклонения от профиля, итоговые рекомендации и компактный план следующего запуска.
- [x] **Сравнение запуска с прошлым успешным прогоном** - для выбранного профиля показывать, где текущий запуск отличался: разгон, стабилизация, скорость отбора, температура верха, давление, cooling margin, energy per liter, и давать быстрый переход в `current vs baseline` compare-view прямо из истории.
- [x] **Рекомендации по настройкам профиля** - на базе history v2 предлагать безопасные правки: снизить/повысить мощность разгона, изменить скорость отбора тела, увеличить стабилизацию, пересчитать объем голов/хвостов.
- [x] **Память рекомендаций между прогонами** - сохранять snapshot `Run Advisor` в JSON истории и на следующем запуске показывать, были ли прошлые советы применены и помогли ли они относительно предыдущего успешного baseline.
- [ ] **Lifecycle гипотез Run Advisor** - отдельным слоем помечать рекомендации как `новая гипотеза`, `проверена`, `подтвердилась`, `не подтвердилась`, но не углубляться в это до завершения более прикладных веб-блоков.
- [x] **Operator Guidance в runtime** - показывать короткие объяснения состояния: "колонна стабилизируется", "отбор разрешен", "риск захлеба растет", "охлаждение на пределе", "конец тела вероятен".
- [x] **Confidence score для решений автоматики** - публиковать 0..100% уверенности для ключевых решений: старт отбора, конец голов, конец тела, переход в хвосты, аварийное ограничение мощности.
- [x] **Recipe learning loop** - после успешного запуска обновлять статистику профиля: средняя длительность, средний выход, средняя энергия, типичные температуры, успешность, последние рекомендации.
- [x] **Pre-flight мастер запуска** - перед стартом режима проверять профиль, датчики, воду, давление, насос, клапаны, мешалку, доступность журналирования и объяснять оператору блокирующие причины.

### Adaptive Recipes и барокоррекция

- [x] **Барокоррекция температурных порогов** - использовать атмосферное давление BMP280 для пересчета ожидаемой температуры кипения и коррекции cut thresholds.
- [x] **Профиль с условиями валидации** - сохранять в профиле давление, конфигурацию колонны, насадку, мощность, объем/крепость сырья и фактические cut points успешного запуска.
- [x] **Автоматическая поправка рецепта на текущие условия** - при загрузке профиля и в runtime-панели ректификации показывать: "рецепт валидирован при 755 мм рт.ст., сейчас 742 мм рт.ст., пороги будут смещены".
- [x] **Адаптивный Smart Decrement v2** - учитывать не только рост температуры верха, но и стабильность колонны, давление, cooling margin, историю предыдущих decrement-событий.
- [x] **Body End Score** - отдельный индикатор вероятности конца тела на базе температуры куба, тренда верха, давления, скорости отбора, объема и стабильности.
- [x] **Heads Completion Score** - оценивать завершение голов не только по объему, но и по времени стабилизации, температурному плато и трендам.
- [x] **Режим dry-run симуляции профиля** - до старта показывать ожидаемую длительность, объемы, расход энергии и основные риски по текущим настройкам.

### Process Indicators v2 как продуктовая фича

- [x] **Публикация indicators в `/api/status` и WebSocket** - `stabilityIndex`, `floodRisk`, `coolingMargin`, `takeoffAllowed`, `bodyEndScore`, `headsCompletionScore`, `sensorFreshnessOk`.
- [x] **Indicators в history v2** - сохранять агрегаты и ключевые точки: min/max/avg stability, max floodRisk, min coolingMargin, моменты запрета отбора.
- [x] **TFT/Web UI карточка "Состояние процесса"** - крупно показывать не сырые датчики, а инженерные признаки: стабильность, риск захлеба, запас охлаждения, разрешение отбора.
- [x] **Live pressure diagnostics в операторском мониторе** - Web UI теперь показывает калиброванное давление куба, скорость его изменения и запас до лимита прямо в `Состоянии процесса` и диагностике, без перехода в сервисные экраны.
- [x] **Reason code -> человекочитаемое объяснение** - для каждого `RC_*` иметь короткий текст причины, влияния на процесс и рекомендуемого действия.
- [x] **Anti-oscillation guard** - блокировать частые переключения фаз/мощности/насоса, если indicators нестабильны или датчики дрожат.
- [x] **Graceful degradation** - при отсутствии части датчиков явно снижать уровень доверия автоматики, а не имитировать полноценный adaptive mode.

### Smart Cooling / Deflegmator Control

- [x] **Cooling margin model** - запас охлаждения теперь считается не только по `T_water_out`, но и с учетом скорости роста `T_water_out`, `TSA`, давления и состояния дефлегматора, чтобы `coolingMarginC` раньше предупреждал о перегрузе охлаждения.
- [ ] **Пропорциональное управление охлаждением** - добавить опциональный исполнитель: servo needle valve, 0-10V клапан, PWM-насос или шаговый игольчатый клапан; частично уже закрыто: в оборудовании и сервисном UI появился базовый PWM-канал охлаждения с окном `min/max duty`, стартовым duty и ручным тестом через `start/stop`.
- [ ] **Closed-loop deflegmator control** - держать целевой режим дефлегматора не ручным краном, а контуром по температуре/давлению/стабильности колонны.
- [ ] **Emergency flood deflegmator** - при критическом событии принудительно открыть охлаждение на максимум, затем отключить нагрев через safety supervisor.
- [ ] **Cooling autotune** - короткий тест перед запуском: открыть/закрыть клапан, измерить реакцию `T_water_out`/потока, оценить достаточность охлаждения.
- [ ] **Water usage metrics** - логировать расход воды, л/час, л/прогон, water per liter product и показывать экономию после настройки.
- [ ] **ATACC-style external module compatibility** - предусмотреть API/пины для отдельного блока управления охлаждением без переделки основной автоматики.

### Smart Cuts Station

- [ ] **Фракционная станция v1** - довести servo/позиции фракций до законченного сценария: головы, тело, хвосты, промежуточные банки, промывка/слив.
- [ ] **Контроль объема или веса приемной емкости** - добавить опциональный HX711/load cell или flowmeter для проверки переполнения и фактического объема фракции.
- [ ] **Защита от переполнения** - если емкость заполнена или датчик невалиден, остановить отбор/переключить в safe vessel/поставить процесс на паузу.
- [ ] **Журнал cut events** - сохранять каждое переключение фракции: время, объем, температура, ABV, давление, причина переключения, позиция сервопривода.
- [ ] **Оценка фракций после прогона** - дать оператору отметить качество/запах/вкус фракций и привязать эту обратную связь к профилю.
- [ ] **Cut map editor** - UI для настройки количества емкостей, углов сервопривода, назначений, лимитов объема и теста каждой позиции.
- [ ] **Aggressive tails strategy** - опционально после подтвержденного перехода в хвосты повышать мощность/скорость отбора для быстрого добора, с отдельными safety-лимитами.

### Безопасность, ввод в эксплуатацию и доверие

- [ ] **Commissioning Wizard** - мастер первого запуска: выбор платы/ревизии, проверка пинов, тест датчиков, тест клапанов, тест насоса, тест SSR, тест safety-реле.
- [ ] **Boot-time self-test GPIO** - при старте проверять опасные пины на безопасное состояние до инициализации драйверов.
- [ ] **Независимое аварийное реле нагрева** - аппаратный dry-contact/relay output, который safety supervisor может отключить независимо от SSR/PWM.
- [ ] **Опциональный датчик паров спирта** - добавить канал gas/vapor sensor как предупреждение, не как единственную защиту; логировать события и блокировать старт при превышении.
- [ ] **Датчик протечки/поддона** - простая дискретная защита от воды/браги в корпусе или под оборудованием.
- [ ] **Safety proof test** - периодический тест аварийных цепей: реле, клапан воды, насос, звуковой сигнал, связь с UI/HA.
- [ ] **Уровни автономности** - режимы `manual`, `guided`, `adaptive`, `full-auto`, чтобы оператор явно понимал, какие решения принимает автоматика.
