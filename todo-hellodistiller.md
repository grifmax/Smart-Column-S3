> Ревизия: 2026-07-15. Источники: HelloDistiller.pdf v5.038.3, код и CHANGELOG.md Smart-Column S3 v2.4.55.
>
> Цель: перенять только полезные процессные решения. Основной тракт отбора SC-S3 — **перистальтический насос + фракционник**. Клапаны остаются бюджетной альтернативой, а не основой архитектуры.

## Обозначения

- [x] Уже реализовано или закрыто существующей архитектурой.
- [ ] Требуется реализовать либо проверить при приёмке.
- P0 — обязательный ближайший этап; P1 — следующий полезный этап; P2 — опциональное развитие.

## Принципы

- [x] Насос — основной исполнитель отбора; скорость задаётся в физических единицах мл/ч.
- [x] В ректификации уже выбирается backend: насос, несколько клапанов или один клапан с фракционником.
- [ ] Новый отбор выполнять через единый координатор: **остановить поток → сменить маршрут → дождаться фракционника → начать отбор**.
- [ ] Клапанный backend использует ту же модель процесса, но имеет ограниченные маршруты и отдельные проверки безопасности.
- [ ] Не копировать «магические» параметры HelloDistiller: датчик, температура, время и объём задаются отдельными полями.
- [ ] Не создавать одинаковые режимы ради разных настроек: применять профили и пресеты.
- [ ] Основные настройки показывать сразу, экспертные раскрывать по запросу в стиле текущего UI.

## 1. Вывод по режимам

### Уже закрыто в SC-S3

- [x] **Авторектификация:** разгон, стабилизация, головы, повторная стабилизация, тело, хвосты, продувка и завершение.
- [x] **Режимы флегмы:** фиксированная скорость, флегмовое число и автономный цикл.
- [x] **CHIM:** температурная, накопительная и стартовая коррекции с минимальным пределом скорости.
- [x] **Мощность по фазам** и **завершение тела по давлению**.
- [x] **Барометрическая коррекция:** настройка, профиль и диагностическая сводка.
- [x] **Отбор голов при дистилляции:** уже встроен отдельной фазой.
- [x] **Термостат и таймер мощности:** в основном закрываются HOLD, ферментацией и ручным режимом.

### Реализовано частично

- [ ] **Дистилляция по фракциям — P0.** Есть насосный отбор голов/тела и маршруты ректификации, но нет произвольной программы фракций.
- [ ] **Зерновой/мучной затор — P1.** Есть температурный профиль до 10 шагов, но нет засыпи, разваривания, охлаждения, осахаривания и перехода к брожению.
- [ ] **Ферментация — P1.** Есть нагрев и длительность, но нет активного охлаждения, расписания мешалки и подготовки к брожению.
- [ ] **НБК — P1.** Есть разгон, стабилизация и постоянная подача, но нет плавного запуска, коррекции подачи и полного набора защит.

### Действительно не хватает

- [ ] **Универсальная программа фракционного отбора — P0.** Главный разрыв относительно HelloDistiller и главный приоритет для нашей схемы.
- [ ] **Полный рецепт приготовления браги — P1.** Развитие MASHING, а не новый дублирующий автомат.
- [ ] **Охлаждение и подготовка к брожению — P1.** Связка между рецептом затора и ферментацией.
- [ ] **Управление мощностью по температуре пара — P2.** Полезная стратегия дистилляции, но не обязательный отдельный режим.
- [ ] **Ограничение мощности ректификации по давлению — P2.** Аналог «эмульгации» только после проверки датчика давления.

## 2. P0 — универсальный фракционный отбор

### 2.1 Программа фракций

- [ ] Добавить профиль из 1–8 последовательных фракций.
- [ ] Для фракции хранить название, маршрут/позицию фракционника, скорость насоса, мощность и условия завершения.
- [ ] Поддержать условия: объём, время, температура выбранного датчика, датчик уровня и ручной переход.
- [ ] При нескольких условиях завершать по первому сработавшему и сохранять точную причину.
- [ ] Не запускать автоматическую фракцию без условия завершения, кроме явно подтверждённого ручного режима.
- [ ] Окончание разгона задавать явно как датчик + температура, без отрицательных значений-переключателей.
- [ ] Хранить программу в профилях с версией схемы и миграцией старых настроек.

### 2.2 Исполнительный тракт

- [ ] Вынести подачу и маршрутизацию в общий takeoff coordinator для ректификации и дистилляции.
- [ ] Для основного тракта использовать калиброванный расход насоса и фактически накопленный объём.
- [ ] Перед сменой ёмкости останавливать насос; запускать после подтверждения позиции и routingSettlingMs.
- [ ] При ошибке серво, недоступном маршруте или потере обратной связи оставлять насос выключенным и ставить процесс на безопасную паузу.
- [ ] Показывать запрошенный и фактический маршрут, скорость, объём фракции и ожидаемый критерий завершения.
- [ ] Добавить действия: Пауза, Продолжить, Следующая фракция, Остановить. Переход назад пока не добавлять.

### 2.3 Клапанный вариант

- [ ] Использовать ту же программу, ограничив маршруты фактическими выходами головы / тело / хвосты.
- [ ] До запуска проверять доступность клапанов и запрещать неподдерживаемую программу.
- [ ] Не выполнять незаметный fallback между насосом и клапанами: backend выбирается явно.
- [ ] Для отбора по пару требовать безопасный выход в атмосферу/ТСА; закрытые клапаны не должны герметизировать куб.
- [ ] Для импульсного управления соблюдать минимальное открытие и показывать эквивалентную скорость.

### 2.4 Дистилляция

- [ ] Сделать «Дистилляцию по фракциям» профилем существующей дистилляции, а не копией FSM.
- [ ] Перевести головы и тело на общий координатор; убрать прямое управление насосом и клапаном из handler-а.
- [ ] Задействовать существующий tailsVolumeMl через программу либо удалить его как ложное обещание UI.
- [ ] Добавить пресеты: Спирт-сырец, Головы + тело, Головы + тело + хвосты, Произвольные фракции.
- [ ] После последней фракции выполнять охлаждение и фиксировать объём каждой ёмкости.
- [ ] Добавить уведомление о заполнении/смене тары с безопасной паузой насоса.

### 2.5 Приёмка P0

- [ ] Проверить каждое условие завершения и комбинации условий ИЛИ.
- [ ] Проверить последовательность pump off → route → settle → pump on.
- [ ] Проверить отказ фракционника, отсутствующий маршрут, уровень, аварийный стоп и продолжение после паузы.
- [ ] Сверить семантику local API, cloud API, live status, профилей, истории и дисплея.
- [ ] Добавить host-side тесты сериализации и чистой логики выбора причины завершения.

## 4. P1 — зерновой/мучной затор и пивоварение

### 4.1 Рецепт

- [ ] Развить MashProfile из температурных пауз в список типизированных технологических шагов.
- [ ] Поддержать: нагрев, выдержку, ожидание оператора, разваривание/кипячение, охлаждение, перемешивание и завершение.
- [ ] Добавить шаблоны: Солодовый профиль, Зерновой затор с развариванием, Мучной затор без разваривания, Охлаждение перед брожением.
- [ ] Таймер выдержки запускать только после входа в температурный допуск — текущий MASHING уже следует этому принципу.
- [ ] Нулевая длительность означает явное подтверждение: засыпь, ферменты/солод, извлечение корзины, внесение хмеля.
- [ ] Разрешить безопасный переход к следующему шагу с записью причины в историю.

### 4.2 Разваривание и охлаждение

- [ ] Определять закипание по датчику пара над затором; предусмотреть резервный порог и таймаут.
- [ ] Для разваривания задавать максимальную мощность и длительность отдельно от обычных пауз.
- [ ] Реализовать периодическое охлаждение водой совместно с мешалкой для экономии воды и выравнивания температуры.
- [ ] Настраивать мешалку по шагам: постоянно, циклически или выключено, с пределом безопасной температуры.
- [ ] Верхний датчик уровня использовать как защиту от пены: останов нагрева, допустимое охлаждение/перемешивание и уведомление.
- [ ] После охлаждения предлагать переход в ферментацию без обязательной автоподачи дрожжей.
- [ ] Автодозирование дрожжей разрешать только отдельным или явно переназначенным насосом; основной насос отбора нельзя занимать неявно.

### 4.3 Без лишних режимов

- [ ] Несколько внесений хмеля оформить уведомлениями от времени начала кипения.
- [ ] Показывать карточку текущего шага: цель, температура, оставшееся время и действие оператора.
- [ ] Не создавать разные FSM для зернового, мучного и пивного сценария: различия задаются шаблоном шагов.
