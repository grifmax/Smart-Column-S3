## Цель и границы

Документ фиксирует **результаты инвентаризации** кода (2.6.0) и план его
уборки. Это не план новых возможностей: ни одна задача здесь не меняет
поведение прибора. Всё, что меняет поведение, идёт отдельными задачами вне
этого документа.

Три направления:

- **мёртвый код** — то, что не компилируется в образ или не вызывается никем;
- **дублирование** — одна и та же логика в нескольких местах;
- **покрытие тестами** — чтобы уборка и последующие правки шли под защитой.

### Правило идентификаторов задач

Каждый чекбокс имеет неизменяемый ID вида `C-###`. На него ссылаются в
обсуждениях, коммитах и отчётах: `C-004 готово`, `C-021 ожидает стендовой
проверки`. При добавлении задачи назначать следующий свободный номер, уже
существующие не перенумеровывать.

Статусы: `[ ]` — не начато, `[~]` — в работе, `[x]` — принято. Подзадачи без
чекбокса — пояснение или критерий приёмки для родительской задачи.

Префикс `C-` не пересекается с `D-###` из `todo-Distiller.md`: там задачи
развития, здесь — гигиена кода.

### Методика измерения

Все цифры получены разбором дерева `src/`, а не на глаз:

- строки кода — построчный разбор с исключением комментариев и пустых строк;
- мёртвые функции — поиск определений верхнего уровня, затем подсчёт вхождений
  идентификатора по всему `src/`; функция считается мёртвой, если её имя
  встречается только там, где она определена;
- дублирование тел — нормализация пробелов и сравнение по SHA-1;
- размер функций — подсчёт по балансу скобок от сигнатуры.

Ограничение методики: мёртвость определяется по тексту. Функция, вызываемая
только через указатель или из макроса, может быть помечена ошибочно — поэтому
перед удалением каждой группы идёт ручная проверка (см. критерии приёмки).

### Поправка к методике: 53 → 3

Первичная инвентаризация насчитала 53 мёртвые функции. При выполнении этапа 0
это число проверили заново по всему дереву и получили **3**.

Причина расхождения: первичный скрипт сканировал только `src/*.cpp` и
`src/*.h`. Он не смотрел:

- **`test/`** — а большинство «мёртвых» функций это чистые `*_logic.h`-хелперы,
  которые и не должны вызываться из прошивки: их проверяют тесты. Функция,
  используемая только тестом, — это не мёртвый код, а работающая проверка;
- **`src/ui/hmi/hmi2_core.inc`** — файл вклеивается в `display.cpp` через
  `#include` и вызывает функции TFT напрямую. 13 функций `display.cpp` из
  списка оказались живыми именно из-за него.

Правильный критерий: имя функции встречается **ровно один раз во всём
проекте** (`src/` + `test/`, включая `.inc`), то есть только в своём
определении. Проверка по этому критерию даёт:

| Файл | Строка | Функция | Удалена |
| --- | ---: | --- | --- |

  фактическое открытие клапана при окне менее периода цикла управления.

### C-035 Проверка фактической барокоррекции автомата

- [~] **C-035** В 2.6.12 добавлен `scripts/test_fsm_pressure_compensation.py`:
  host-тест извлекает реальные функции `getAtmosphereHpa` и
  `pressureAdjustedCubeTemp` из `fsm_utils.cpp` и константы из `config.h`.
  Проверены оба рабочих порога, коррекция, `ok=false`, строгие границы
  диапазона, соседние значения и NaN/бесконечности (19 проверок).

  Изначально пункт ошибочно ссылался на `safety_policy.h`: расчёт порогов
  находится в `fsm_utils.cpp`. Тест характеризует текущую реализацию, но не
  доказывает работу фаз и датчиков; BMP280 находится в корпусе с наддувом,
  а `pressure.ok` относится к датчику куба. Из-за этой связки пункт остаётся
  открытым до решения C-037 и проверки на стенде; корректность физического
  атмосферного давления и действие переключателя тестом не подтверждены.

### C-036 Усечение текста по границе UTF-8

- [x] **C-036** Добавлен `src/control/text_bounds.h`: `utf8SafeLength` и
  `copyUtf8` — чистое усечение строки по размеру буфера без разрыва

  Появился как механизм C-026: держать границу по байтам надо было в двух

  Заголовок без Arduino, поэтому проверяется нативно: набор

  1 до 32 с проверкой, что результат остаётся корректным UTF-8, и что
  четырёхбайтовый символ отбрасывается целиком, а не наполовину.

### C-037 Барокоррекция не слушает собственный переключатель

- [ ] **C-037** Найдено при разборе C-030, к уборке относится только тем, что
  это висящая связка.

  `fsm_utils.cpp::pressureAdjustedCubeTemp()` поправляет порог на давление
  **всегда**:

  ```
  return baseTempC + (hpa - RECT_PRESSURE_STD_HPA) * RECT_TEMP_COMP_C_PER_HPA;
  ```

  А настройка `rectParams.baroCorrectionEnabled` встречается только в
  `display.cpp` (экран БАРО ВКЛ/ВЫКЛ), в `api/*.cpp` и в веб-исходниках —
  в `src/control/` её нет ни разу. То есть переключатель меняет надпись и
  сохраняется в NVS, но расчёт его не читает: при выключенной коррекции порог
  всё равно сдвигается.

  При 730 мм рт.ст. и коэффициенте 0,049 °C/гПа сдвиг относительно
  1013,25 гПа составляет примерно −1,96 °C, если показание прошло проверку
  диапазона. При невалидном показании берётся стандартное давление, и сдвига
  нет. BMP280 данного прибора находится в корпусе с наддувом — его показания
  пока не считать атмосферным давлением для эксплуатации.
  Дополнительно: `pressure.ok` характеризует чтение датчика куба (ADS1115),
  а не исправность BMP280; переключатель учитывается отдельно при коррекции
  профиля в `profiles.cpp`, но не в этих порогах автомата.

  Это **не** задача уборки: здесь надо решить, что правильно — гасить
  коррекцию по флагу или убрать флаг из UI как всегда включённую функцию.
  Пока решение не принято, поведение не менялось.

  Критерий приёмки: решение зафиксировано в этом пункте, реализовано отдельным
  коммитом с записью в CHANGELOG, и на стендовом прогоне порог на экране
  совпадает с порогом, по которому реально переключается фаза.

## Критерии готовности этапа

**Этап 0 закрыт**, когда:

- сборка успешна, `firmware.bin` после C-001 побайтово равен образу до правки;
- 128 нативных тестов зелёные;
- `grep` не находит ни одного из удалённых идентификаторов;
- `#if 0` в `src/` не осталось.

**Этап 1 закрыт**, когда:

- каждая сведённая функция существует ровно в одном месте;
- ответы `/api/status`, `/api/calibration` и облака не изменились по ключам.

**Этап 2 закрыт**, когда:

- множества ключей состояния в трёх потребителях совпадают;
- список путей облака совпадает со списком локальных `/api/*`.

**Этап 3 закрыт**, когда:

- `*_logic.h` без тестов не осталось, либо отсутствие теста обосновано
  записью в этом документе;
