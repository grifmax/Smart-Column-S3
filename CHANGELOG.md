# Журнал изменений

Все значимые изменения в этом проекте будут документированы в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
и этот проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

---

## [1.4.12] - 2026-01-17

### Исправлено
- Убраны паузы насоса: DS18B20 переведены в неблокирующий режим, генерация шагов вынесена в отдельную задачу.
- Оптимизирован WebSocket broadcast: быстрый пакет чаще, полный — реже, без зависаний при навигации.

---

## [1.4.11] - 2026-01-11

### Добавлено
- Режимы **затирки (mashing)** и **выдержки (hold)**: запуск через API, отображение в Android, отдача статуса (цель/шаг/остаток).
- API ручного управления: управление **ТЭН/насос/клапаны** из `manual.html`.

### Исправлено
- Пауза процесса теперь **безопасная**: выключает исполнительные механизмы и корректно восстанавливает таймеры при resume.
- Возвращена инициализация насоса (`Pump::init()`), синхронизация объёма/скорости в `SystemState`.

---

## [1.4.10] - 2026-01-10

### Добавлено
- 🌐 **Гибридный режим UI (local vs cloud)** — при прямом открытии UI на ESP32 не используются `/api/web/*`, а cloud-only элементы скрываются
- 🆔 **Публичный стабильный идентификатор устройства**: `board.deviceId` в `GET /api/version` (12-символьный hex из eFuse/MAC)
- 💳 **Задел под платные услуги** на web-proxy: таблицы `schema_version` и `user_entitlements`, поле `entitlements` в `/api/web/user`

---

## [1.4.2] - 2025-12-12

### Добавлено
- 📤📥 **Импорт/Экспорт профилей**
  - Экспорт одного профиля в JSON файл (кнопка 📤 на каждом профиле)
  - Экспорт всех профилей (с опцией включения встроенных рецептов)
  - Импорт профилей из JSON (один профиль или массив профилей)
  - Предпросмотр перед импортом
  - Автоматическая генерация новых ID при импорте
  - Сброс статистики для импортированных профилей

### API Endpoints
- `GET /api/profiles/{id}/export` - экспорт одного профиля
- `GET /api/profiles/export?includeBuiltin=true` - экспорт всех профилей
- `POST /api/profiles/import` - импорт профилей из JSON

### Функции backend
- `exportProfileToJSON()` - экспорт профиля в JSON строку
- `exportAllProfilesToJSON()` - экспорт всех профилей
- `importProfileFromJSON()` - импорт профиля из JSON
- `importProfilesFromJSON()` - импорт массива профилей

---

## [1.4.1] - 2025-12-12

### Добавлено
- 📁 **Система профилей процессов**
  - Сохранение настроек процессов под именем для повторного использования
  - Модуль `profiles.h` / `profiles.cpp` для управления профилями в SPIFFS
  - JSON схема хранения профилей с метаданными, параметрами и статистикой
  - Валидация профилей при сохранении
  - Ротация профилей (до 100 профилей, 10 встроенных рецептов)

- 📚 **Библиотека встроенных рецептов**
  - Рецепт "Сахарная брага 40%" - классическая ректификация
  - Рецепт "Зерновая брага 12%" - бережная ректификация с сохранением органолептики
  - Рецепт "Фруктовая дистилляция" - дистилляция с сохранением ароматики

### API Endpoints
- `GET /api/profiles` - получение списка всех профилей
- `GET /api/profiles/{id}` - получение полных данных профиля
- `POST /api/profiles` - создание нового профиля
- `PUT /api/profiles/{id}` - обновление профиля
- `DELETE /api/profiles/{id}` - удаление профиля
- `POST /api/profiles/{id}/load` - загрузка профиля в текущие настройки
- `DELETE /api/profiles` - очистка всех пользовательских профилей

### Документация
- Создан `docs/PROFILES_SCHEMA.md` с полным описанием схемы хранения профилей
- Описание структуры JSON, категорий профилей и API endpoints
- Примеры использования на JavaScript

## [1.3.2] - 2025-12-08

### Добавлено
- 🔔 **Push-уведомления через Home Assistant**
  - Функция `publishNotification()` в MQTT модуле
  - Публикация в два MQTT топика: `notification` (sensor) и `notify` (notify service)
  - Автоматические эмодзи в зависимости от уровня (ℹ️ info, ⚠️ warning, ❌ error, ✅ success)
  - Sensor "Last Notification" в Home Assistant Discovery

- **Интеграция уведомлений в FSM (конечный автомат)**
  - Уведомления о запуске процесса
  - Уведомления о смене фаз (Разогрев → Стабилизация → Отбор голов → Отбор тела)
  - Уведомление о завершении процесса с объемом собранного продукта
  - Уведомление об остановке процесса пользователем

- **Интеграция уведомлений в систему безопасности**
  - Прорыв паров (критическая температура TSA)
  - Перегрев воды охлаждения
  - Захлёб колонны (с автоматическим снижением мощности)
  - Потеря связи с датчиками температуры

- **Интеграция уведомлений в обработчик ошибок**
  - Уведомления для обычных ошибок (warning)
  - Уведомления для критических ошибок (error)
  - Уведомления для фатальных ошибок (error)

### Документация
- Обновлён `HOME_ASSISTANT.md` с полным разделом о push-уведомлениях
- Примеры автоматизаций для мобильных и Telegram уведомлений
- Примеры карточек для отображения последнего уведомления
- Описание всех типов уведомлений

## [1.3.0] - 2025-12-07

### Добавлено
- 📜 **История процессов** - система хранения и анализа завершённых процессов
  - Автоматическое сохранение процессов в SPIFFS при завершении
  - JSON-формат хранения с метаданными, метриками и временными рядами
  - Ротация истории (хранение до 50 последних процессов)
  - Автоматическая очистка старых процессов при превышении лимита

- 📊 **Детальный просмотр процесса**
  - Модальное окно с полной информацией о процессе
  - Интерактивные графики температур (ApexCharts)
  - График мощности и энергопотребления
  - Таблица собранных фракций (головы, тело, хвосты)
  - Метрики процесса (длительность, средняя мощность, энергия)

- 📤 **Экспорт данных**
  - Экспорт отдельного процесса в JSON
  - Экспорт отдельного процесса в CSV
  - Экспорт всей истории в JSON
  - Автоматическая загрузка файлов через браузер

### API Endpoints
- `GET /api/history` - получение списка всех процессов
- `GET /api/history/{id}` - получение детальной информации о процессе
- `GET /api/history/{id}/export?format=json|csv` - экспорт процесса
- `DELETE /api/history/{id}` - удаление процесса из истории
- `DELETE /api/history/clear` - очистка всей истории

### JavaScript (app.js)
- Функция `loadHistory()` для загрузки списка процессов
- Функция `renderHistoryItem()` для отображения элемента истории
- Функция `viewProcess()` для детального просмотра
- Функция `deleteProcess()` для удаления процесса
- Функция `exportProcess()` для экспорта в JSON/CSV
- Функция `exportAllHistory()` для экспорта всей истории
- Функция `clearHistory()` для очистки всей истории

### UI/UX
- Новая вкладка "История" в веб-интерфейсе
- Список процессов с ключевой информацией (дата, длительность, объём)
- Кнопки управления (просмотр, экспорт, удаление)
- Адаптивный дизайн для мобильных устройств
- Поддержка темной темы

### Документация
- Создан `HISTORY_SCHEMA.md` с описанием формата хранения
- Примеры структуры данных JSON
- Описание API endpoints для работы с историей

## [1.2.0] - 2025-11-20

### Добавлено
- 🏠 **Home Assistant Integration**
  - Автоматическое обнаружение через MQTT Discovery
  - Публикация состояния и метрик в реальном времени
  - Интеграция с Energy Dashboard

- 📡 **MQTT Client**
  - PubSubClient для публикации данных
  - Топики для температур, мощности, энергии, здоровья системы
  - Last Will and Testament (LWT) для индикации доступности
  - Настраиваемый интервал публикации

- 🔒 **Безопасность**
  - HTTP Basic Authentication для веб-интерфейса и API
  - Rate Limiting (60 req/min на IP)
  - Security Headers (CSP, X-Frame-Options, и др.)
  - Защита от DDoS атак

- ⚡ **PZEM-004T Support**
  - Точный мониторинг напряжения, тока, мощности
  - Измерение потреблённой энергии
  - Интеграция с Energy Dashboard в Home Assistant
  - Детектирование аномальных значений

### Документация
- Создан `API.md` с полной документацией REST API, WebSocket и MQTT
- Создан `HOME_ASSISTANT.md` с руководством по интеграции
- Примеры автоматизаций и dashboard карточек
- Troubleshooting секция
