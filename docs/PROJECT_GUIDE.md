# Smart-Column S3 — описание проекта и инструкция

## Что это

Smart-Column S3 — это прошивка и Web UI для автоматики на базе `ESP32-S3`, которая управляет колонной и соседними технологическими режимами:

- авто-ректификация
- ручная ректификация
- дистилляция
- затирание
- пастеризация / hold
- НБК
- ферментация

Проект не ограничивается простым включением нагрева и насоса. Он собирает телеметрию, пишет историю прогонов, ведёт профили, публикует инженерные indicators, объясняет состояние процесса оператору и готовит базу для повторяемой настройки рецептов.

## Основная идея проекта

У большинства самодельных автоматики есть две типовые проблемы:

1. Они умеют что-то включать и выключать, но плохо объясняют оператору, что именно происходит.
2. После удачного прогона знания не сохраняются в виде удобного baseline для следующего запуска.

Smart-Column S3 строится вокруг другой модели:

- оператор в основном работает из Web UI на телефоне, планшете или ноутбуке
- локальный TFT нужен как параллельная панель контроля и ручного вмешательства
- каждый прогон должен не только завершиться, но и оставить после себя историю, понятные причины событий и основу для следующего улучшения профиля

## Из чего состоит система

### Прошивка

Прошивка находится в `src/` и отвечает за:

- FSM и логику режимов
- safety и recovery-логику
- работу с датчиками, насосом, клапанами, нагревом и мешалкой
- REST API, WebSocket, OTA, MQTT и cloud tunnel
- историю процессов и профили

### Web UI

Web UI собирается из `src/web/` в `data/` и отвечает за:

- схему установки
- мониторинг и диагностику
- управление режимами
- сервисные действия и калибровки
- историю прогонов и `Run Advisor`

### TFT-интерфейс

TFT остаётся локальным инженерным экраном:

- текущие температуры и статусы
- быстрый контроль режима
- аварийный/сервисный доступ рядом с оборудованием

## Аппаратная база

Базовая целевая конфигурация:

- `ESP32-S3 DevKitC-1 N16R8`
- `DS18B20` для температур
- `аналоговый датчик давления + ADS1115` для давления куба (`A1`) и отдельного канала ареометра (`A0`)
- второй `ADS1115` (`0x49`) заранее отведён под уровни приёмных ёмкостей, чтобы не мешать основному измерительному контуру
- `BMP280` для атмосферного давления
- `SSR + PZEM-004T` для нагрева и энергии
- `TMC2209` для насоса
- `MCP4725 + MCP6001` для мешалки `0-10В`
- `ILI9488 + XPT2046` для TFT

Подробный pinout и железо описаны в [SPEC.md](../SPEC.md).

## Как проектом пользоваться оператору

### Первый запуск

1. Залить прошивку и файловую систему.
2. Подключиться к точке доступа `Smart-Column-S3`, если Wi‑Fi ещё не настроен.
3. Открыть Web UI и настроить:
   - Wi‑Fi
   - оборудование
   - safety-пороги
   - насос, клапаны, мешалку
4. Проверить датчики и исполнительные механизмы через сервисные страницы.

### Рабочий сценарий

1. Выбрать или загрузить профиль.
2. Проверить показометры, охлаждение и состояние оборудования.
3. Настроить параметры режима.
4. Открыть `Pre-flight` мастер запуска.
5. Подтвердить запуск только после зелёного или понятного жёлтого статуса.
6. Во время прогона следить за:
   - guidance
   - stability / flood risk / cooling margin
   - историей событий и safety
7. После завершения открыть историю и посмотреть `Run Advisor`.

## Как проектом пользоваться разработчику

### Основные каталоги

```text
src/control/      режимы, FSM, v2 indicators, safety
src/drivers/      железо: датчики, насос, клапаны, экран, мешалка
src/interface/    webserver, mqtt, ota, tunnel, security
src/storage/      NVS, logger, история
src/web/          исходники frontend
data/             собранные web-ассеты для LittleFS
docs/             проектная документация
```

### Базовый цикл разработки

1. Меняем прошивку в `src/` или frontend в `src/web/`.
2. Если менялся frontend — запускаем `npm run build`.
3. Если менялась прошивка — запускаем `pio run -e esp32s3`.
4. Для значимого изменения поднимаем версию в `src/config.h`.
5. Добавляем запись в `CHANGELOG.md`.

### Правила релиза в этом проекте

- версия прошивки должна совпадать в `src/config.h`, `README.md`, `CHANGELOG.md` и `data/version.json`
- после значимых изменений нужен коммит
- после коммита нужен `git push`
- проектовые текстовые файлы держим в `UTF-8`

## Что уже умеет Smart-Column S3

- process history v2
- профили и learning summary
- runtime guidance
- confidence score для решений автоматики
- pre-flight мастер запуска
- Run Advisor v1: post-run отчёт по фазам, энергии, устойчивости, safety и baseline профиля
- сравнение текущего запуска с прошлым успешным прогоном по профилю
- память рекомендаций между прогонами
- validation context профиля: условия, при которых последний успешный baseline действительно был получен
- мягкая барокоррекция профиля с возможностью отключения в настройках ректификации

- adaptive recipes

- более формальная работа с baseline и recipe learning loop
