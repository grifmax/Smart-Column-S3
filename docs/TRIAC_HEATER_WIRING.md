# TRIAC Heater Wiring

Памятка по узлу фазового управления нагревом в `Smart-Column S3`.

Документ нужен для двух вещей:
- быстро проверить совместимость оптодрайвера и прошивки;
- не перепутать подключение силового симистора, особенно `G`, `A1` и `A2`.

---

## 1. Какой оптодрайвер нужен

Для текущего backend фазового управления в прошивке нужен `random-phase` оптодрайвер:

- `MOC3021`
- `MOC3023`
- совместимые аналоги этого класса

`MOC3063` и похожие `zero-cross` оптодрайверы не являются штатным вариантом для текущего фазоимпульсного алгоритма. Их имеет смысл использовать только под отдельный `burst-fire` / `packet control` backend.

Практический вывод для проекта:
- штатная связка `Smart-Column S3` -> `MOC3021/MOC3023` -> силовой симистор;
- `MOC3063` не использовать как drop-in замену для phase control.

---

## 2. Текущая логика прошивки

Ветка нагрева сейчас работает так:

1. `GPIO45` получает `zero-cross`.
2. Прошивка отсчитывает задержку после перехода через ноль.
3. `GPIO46` выдаёт короткий `gate pulse` на вход оптодрайвера.
4. Оптодрайвер открывает силовой симистор в нужной точке полупериода.

По состоянию на `2.2.92+`:
- `TRIAC_PULSE_WIDTH_US = 150`
- есть блокировка повторного фронта `zero-cross` внутри того же полупериода
- в Web UI видно не только `zero-cross`, но и `gate pulses`

---

## 3. Правильная силовая обвязка

Критически важный момент:

- `G` силового симистора должен идти к выходу оптодрайвера и далее к ветке `A2`
- `A1` не является точкой, куда нужно сажать gate в этой схеме

Если коротко:

```text
MOC3021 / MOC3023 output -> resistor -> TRIAC G
same output reference branch -> TRIAC A2
load branch -> TRIAC main terminals A1/A2 according to chosen power schematic
```

Самая частая ошибка, из-за которой “всё зелёное, а нагрева нет”:

- `zero-cross` есть
- `PZEM` жив
- `GPIO46` стреляет
- но `G` силового симистора ошибочно привязан к `A1`, а не к `A2`

Именно в таком случае управляющая логика выглядит рабочей, а силовой канал не открывается как надо.

## 5. Что видно в сервисном экране

В `Оборудование -> Тестирование -> Нагрев` для phase-control полезны три индикатора:

- `Zero-cross` — ESP32 реально видит синхронизацию с сетью
- `Gate pulses` — прошивка реально выдаёт управляющие импульсы на `GPIO46`
- `PZEM мощность` — силовой канал реально пропускает энергию в нагрузку

Диагностика читается так:

- `Zero-cross` растёт, `Gate pulses` растут, `PZEM мощность` растёт:
  узел работает штатно
- `Zero-cross` растёт, `Gate pulses` растут, `PZEM мощность` не растёт:
  проблема почти наверняка в силовой части, оптодрайвере или подключении `G/A1/A2`
- `Zero-cross` есть, `Gate pulses` не растут:
  проблема в firmware path или в логике запуска теста
- `Zero-cross` нет:
  сначала чинить детектор нуля

## 6. Замечание по MOC3021

`MOC3021` может работать, но он более чувствителен к току LED-входа, чем `MOC3023`.

Если `MOC3021` запускается нестабильно:
- сначала проверить ток через входной LED оптодрайвера;
- затем проверить номинал резистора на входе оптодрайвера;
- затем уже трогать силовую часть.

Если нужен максимально беспроблемный штатный вариант для этой прошивки, предпочтительнее `MOC3023`.
