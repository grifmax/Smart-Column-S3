# TODO: внедрение TFT HMI v2 в железо

Рабочий чеклист миграции локального меню 480×320 (ILI9488 + XPT2046) на модель
из `docs/TFT_MENU_REDESIGN.md`: плоские страницы, строки с инлайн-управлением,
`СТОП ВСЁ` только в режиме проверки оборудования, нижняя панель.

Прототип: `docs/prototype/tft-menu-v3.html` (актуальная геометрия B;
`tft-menu-v2.html` — тот же файл под старым именем). Текущий экранный слой:
`src/drivers/display.cpp` (~14 тыс. строк, 25 экранов плюс каркас `hmi2*`).
Правила проекта: `GEMINI.md` — версия + запись в `CHANGELOG.md` на каждое
изменение, host-тесты и сборка перед заливкой.

Состояние: **геометрия зафиксирована, каркас и главный экран уже в прошивке;
остальные разделы пока на старом рендерере.**

## Ф-1. Клапан охлаждения: остатки

Медленный цикл 1–600 с отменён: клапан не открывают «на время» ради доли потока.
Нужен двухпозиционный клапан и PWM только для снижения тока катушки.

- [x] `Valves`: медленный цикл убран из `update()`, выход 0 или уровень удержания
- [x] Втягивание 300 мс на 100 % перед переходом на удержание
- [x] Частота LEDC 20 кГц вместо 1 кГц
- [x] `Втягивание, мс` вынесено в настройки (по умолчанию 300 мс)
- [x] Дескрипторы используют `COOLING_PWM_HOLD_PERCENT` и `COOLING_PWM_PULL_MS`
- [x] Удержание задаётся и хранится процентом (5–100%), а не уровнем `0..255`
- [x] Удалены `coolingPwmPeriodSec`, NVS-ключ `cool_pwm_per` и старые min/max/startup поля
- [x] Host-тесты: процент → заполнение, границы 5–100 %, поведение при 0/100 %
- [ ] После OTA проверить на слух отсутствие гула и нагрев катушки
