## 1. Базовый принцип

### 1.1 Что делаем [TODO]

Нужно сделать **единый контур управления отбором**, который умеет работать через разные исполнительные механизмы:

- `PUMP` — перистальтический насос
- `VALVE_MULTI` — несколько клапанов по фракциям
- `VALVE_SINGLE_SWITCHED` — один клапан отбора, а фракция выбирается переключением тракта

Логика ректификации должна оперировать не `Pump::start()` и не `Valves::setStartStop()` напрямую, а абстрактной командой:

- `fraction = heads/body/tails`
- `equivalentTakeoffRateMlH`
- `fullReflux`
- `periodicTakeoff`
- `takeoffEnabled`

### 1.2 Почему это важно [TODO]

Сейчас в коде автоматическая ректификация в основном завязана на насос.
Для клапанов это плохо по двум причинам:

- `CHIM` в HelloDistiller управляет ШИМ клапана, а не скоростью насоса
- периодический отбор голов и удержание клапана требуют другой физики управления

Вывод:

- `CHIM` должен стать **нейтральной коррекцией интенсивности отбора**
- уже ниже backend сам переводит это в:
  - `мл/ч` для насоса
  - `duty/open-time` для клапана

## 2. Аппаратные варианты

### 2.1 Вариант A: 3 клапана на разные фракции [TODO]

Схема:

- отдельный клапан `HEADS`
- отдельный клапан `BODY`
- отдельный клапан `TAILS`

Плюсы:

- простая логика выбора фракции
- легче диагностировать
- меньше риска смешивания при неправильном переключении
- проще реализовать периодический отбор для голов отдельно от тела

Минусы:

- больше железа
- больше GPIO/драйверов
- больше сценариев отказа

Что потребуется:

- расширить драйвер клапанов новым состоянием для `BODY` и `TAILS`
- добавить безопасное взаимоисключение: одновременно открыт только один продуктовый клапан
- добавить тесты и UI для всех трёх каналов

### 2.2 Вариант B: 1 клапан на все фракции через переключение [TODO]

Схема:

- один общий клапан отбора
- отдельный механизм переключения тракта по фракции

Переключатель может быть:

- сервопривод фракционатора
- отдельные распределительные клапаны
- УНО/байпас при подходящей гидравлике

Плюсы:

- меньше клапанов отбора
- меньше нагрузка по питанию
- проще удержание одного рабочего клапана

Минусы:

- сложнее маршрутизация фракции
- нужен контроль порядка: сначала переключить тракт, потом открыть отбор
- выше цена ошибки в автоматики переключения

Что потребуется:

- единый `takeoff valve`
- отдельная сущность `fraction routing`
- защита от открытия на неверной позиции переключателя

### 2.3 Что должно быть общим для обоих вариантов [TODO]

## 6. Логика по вариантам

### 6.1 Вариант A: 3 клапана [TODO]

Нужна логика:

- `HEADS`:
  - открыть только heads valve
  - остальные продуктовые клапаны закрыты
- `BODY`:
  - открыть только body valve
- `TAILS`:
  - открыть только tails valve

Проверки:

- запрещено открывать два продуктовых клапана одновременно
- при смене фракции сначала закрыть предыдущий, потом открыть новый
- авария должна закрывать все три
- `[DONE]` старт блокируется, если для backend `VALVE_MULTI` не хватает `HEADS/BODY/TAILS` клапанов

### 6.2 Вариант B: 1 клапан + переключение [TODO]

Нужна логика:

- перевести маршрутизатор в нужную фракцию
- дождаться `routingSettlingMs`
- при необходимости подтвердить позицию
- только после этого открыть общий клапан отбора

Проверки:

- если маршрутизация не готова — отбор запрещён
- если положение не подтверждено — отбор запрещён
- при смене фракции сперва закрыть отбор, потом переключать тракт
- `[DONE]` старт блокируется, если нет включенного фракционатора или недоступен общий клапан отбора
